# Adversarial review

Review scope: the delivered token, fee/voting implementations, transparent proxy, CREATE2 deployment helper, dependencies, and actual v4 delta settlement. The revision additionally reviews the immutable implementation restrictions and the input-prepaying swap router against reproduced contributor findings. This is a separate adversarial pass by the implementing contributor, not an independent contributor's audit. No production transaction, funded wallet, or live fork was used.

## Callback and delta analysis

Every one of the ten callback functions checks the namespaced PoolManager address. The full unauthorized-callback test checks returned revert bytes, including unused callbacks and afterSwap. The single pool is bound by beforeInitialize to the configured paper token and fixed IMD; only the initializer helper or application owner can initialize it. Pool ID validation prevents use for a different fee/spacing/key, and rebinding is rejected. Initialization and helper deployment are atomic, so a reverted pool initialization cannot leave a partially configured proxy.

All fourteen address flags and permission fields match. The liquidity and donation return deltas are zero; lifecycle tests donate and remove the real position without charging fees. beforeSwap returns zero for paper-specified modes, and only a positive IMD specified fee otherwise. Exact-input fee is 2% of the gross budget and cannot cancel the entire AMM swap. Exact-output IMD gross-up requests the AMM amount necessary to provide the caller's original net output. afterSwap returns a positive fee only for the unspecified IMD leg. It returns zero when beforeSwap already charged, preventing double fees. No callback uses a caller-selected recipient, rate, target, or router-supplied voter identity.

`manager.take(IMD, recipient, amount)` creates a hook debit for each payment. The sum of these debits is exactly the positive returned IMD fee delta. The manager's post-callback accounting credits that delta to the hook and subtracts it from the caller's delta. The test router uses `sync -> transferFrom -> settle` for debts and `take` for credits; its unlock completes only when every manager delta is zero. Unit tests compare trader, manager, both wallets, and the hook after each swap. The stateful invariant interleaves all four swap modes, all valid splits, posts, and burns, then checks aggregate expected fees/burns, total supply, no hook balances, no remaining hook/router deltas, zero nonzero-delta count, and a locked manager.

There is no arbitrary AMM replacement, full-input NoOp return, LP fee override, rescue function, claim balance, payable hook entry, unbounded on-chain voting loop, or `tx.origin` authorization. Salt search is bounded to 200,000 candidates and intended for off-chain simulation; it is not a swap path. The explicit signed bounds reject int256 minimum and amounts outside int128 before encoding return deltas.

## Upgrade analysis

OpenZeppelin Contracts 5.4.0 supplies the transparent proxy and ProxyAdmin. The custom proxy adds no external selectors. It fixes ProxyAdmin initial ownership in its creation code, requires all fourteen bits, and requires the exact initialization selector and ABI length. Before the base constructor delegates, it validates the entire candidate runtime against the pinned V1/V2 hashes, with only the 32-byte manager immutable normalized to zero. The manager word must encode an address with code; that address is captured immutably in the proxy. Every upgrade revalidates the runtime and requires the same manager. The runtime hashes and manager cannot be changed by either owner. Thus getters, delegate-forwarding shims, changed fee instructions, changed callbacks, or storage-writing replacements cannot pass admission. Canonical runtime deployment/upgrade tests also detect compiler or source drift that would invalidate these hashes.

The implementation constructor disables its initializer; proxy initialization runs in the constructor and cannot be seized between transactions. A plain user, application owner, or direct call from the dev wallet cannot invoke the proxy upgrade path. Only the proxy's ProxyAdmin contract can; only its owner can instruct it. The ProxyAdmin contract cannot accidentally call application functions through the transparent proxy. V1/V2 retain the same state, math, and all fourteen flags. Future code beyond these two implementations requires a new proxy; this is the explicit constraint needed to keep the cap permanent.

Application state uses the computed ERC-7201 namespace, independently verified in the upgrade test. That test snapshots the entire occupied namespace region, upgrades through ProxyAdmin, compares the raw slots, and then trades, burns against an old ID, and posts a new ID. The old split survives even though the fresh-V2 default differs. Attempting to initialize again during an upgrade reverts the upgrade transaction and preserves the old implementation. V2 adds no slots and changes only `_defaultSplit`. Initializable uses its own namespace; ERC-1967 proxy slots are disjoint.

## Verification and remaining release work

Foundry unit, fuzz, and stateful tests run without RPC or environment reads against real local PoolManagers. Default fuzzing uses 256 inputs per fuzz test; the invariant runs 64 sequences of depth 32 with `fail_on_revert = true`. The revised delivered suite contains 118 passing tests, with no skips. Compiler 0.8.26 build and format checks pass. The supplied fee-cap proof also passes independently. The reproduced, disputed first-buy and opcode-admission proofs still fail for the reasons above; their scratch copies were removed from the default suite, not altered or described as passing. A separate revision review checked all 44 router/upgrade tests and found no further actionable defect.

The original gas report measured V1 beforeSwap up to approximately 89,198 gas and afterSwap up to 79,494 gas across success/failure paths and fixtures. These pre-revision local measurements are not a promise for mainnet token behavior. Revised runtime sizes: Paper 1,723 bytes, both implementations 11,883 bytes, proxy 1,583 bytes, deployment helper 10,940 bytes, swap router 3,726 bytes; all below EIP-170. Init code also stays below EIP-3860 limits.

Foundry lint warnings were examined: guarded/revert-bounded integer casts, fixed-prefix ABI concatenation for deterministic creation bytes, events following guarded external calls, manager initialization's unused return tick, and exact token-delivery comparison are intentional. The quote intentionally uses only sqrtPriceX96 from slot0. Token allocation calls only the known Paper token; deployment has no shared mutable allocation state. The router timestamp comparison implements a user deadline, not randomness. Its callback hash is temporary transaction authentication rather than an administratively changed role. Access modifiers preceding `nonReentrant` only read namespaced storage and make no external calls. The targeted arbitrary-send-erc20 lint passes without suppression. These results are not represented as an independently clean static-analysis report. Slither, Mythril, formal verification, live fork testing, external audit, and a bug bounty were not run.

Before mainnet release an independent contributor must review this code, the restricted upgrade policy, the first-buy proof dispute, and the outstanding delegatecall admission conflict; verify the live manager/IMD and the pre-settlement router integration; approve the IMD/USD maintenance procedure and spot-price limitation; approve launch price/ranges/funding/LP custody; rehearse with live chain state; verify deployed code and ownership; and arrange upgrade/parameter/event monitoring. This repository is a locally checked deliverable, not evidence that these release steps occurred.
